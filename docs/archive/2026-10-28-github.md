# Organização do GitHub — 28 de outubro de 2026

Registro desta etapa de manutenção. Para o fluxo vigente, consulte a [governança](../GOVERNANCA_REPOSITORIO.md); para o aplicativo, use o [portal](../README.md).

## Organização aplicada

- README com downloads, canais de versão, capturas reais e entradas separadas para uso e desenvolvimento.
- Portal de documentação, índice histórico, páginas atuais de estado e arquitetura e guia local sem referências de versão obsoletas.
- Guias de suporte e contribuição, formulários curtos de problema e melhoria e modelo de pull request.
- Convenções de texto, proteção de arquivos locais pelo Git e verificação automatizada de estrutura e links.
- Os checks `tests` e `repository` são definidos para todos os PRs; fluxos de distribuição manual ficam serializados por branch.
- Dezesseis labels com descrições em português, incluindo áreas do aplicativo e manutenção. Os nomes convencionais existentes foram preservados.

Esta etapa não mudou o código da aplicação, a base integrada, os pacotes da RC2, as tags ou os termos de distribuição. Documentos e evidências antigos mantêm seus caminhos.

## Configurações administrativas pendentes

A autenticação da integração permitiu branches, labels e pull requests, mas o GitHub recusou alterações administrativas de About, tópicos e relato privado de vulnerabilidades com **HTTP 403 — Resource not accessible by integration**. A consulta à proteção clássica de `main` também foi recusada; a proteção não deve ser declarada ativa.

As definições revisadas ficaram em [repository-settings.json](../../.github/repository-settings.json), com o utilitário [configure_repository.py](../../tools/configure_repository.py). O modo padrão é somente leitura e distingue itens já configurados de pendências ou seções sem permissão. O proprietário pode aplicar as seções usando sua própria autenticação administrativa, conforme o [guia](../GOVERNANCA_REPOSITORIO.md#aplicar-a-configuração-administrativa).

A ausência de permissão da integração não foi contornada nem tratada como configuração concluída. O status administrativo deve ser conferido novamente após uma alteração de permissão ou aplicação pelo proprietário.
